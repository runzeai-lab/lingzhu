### 组件详解

#### 1️⃣ PerformanceMonitor（性能监控器）

**功能**：监控代码性能（响应时间、内存使用、CPU 占用）。

**监控指标**：
- 📊 **响应时间**：平均响应时间、最大响应时间、最小响应时间
- 💾 **内存使用**：函数执行期间的内存占用（MB）
- 📈 **CPU 使用率**：函数执行期间的 CPU 占用（%）
- 🔢 **调用次数**：函数的调用次数
- ❌ **错误次数**：函数执行失败的次数

**核心方法**：
- `start_monitoring(module_name)` - 开始监控指定模块
- `stop_monitoring(module_name)` - 停止监控指定模块
- `collect_metrics(...)` - 收集性能指标
- `get_metrics_summary(...)` - 获取性能指标摘要

**输出**：`PerformanceMetrics` 对象列表，包含：
- `module_name`：模块名称
- `function_name`：函数名称
- `avg_response_time`：平均响应时间（秒）
- `max_response_time`：最大响应时间（秒）
- `min_response_time`：最小响应时间（秒）
- `memory_usage_mb`：内存使用（MB）
- `cpu_usage_percent`：CPU 使用率（%）
- `call_count`：调用次数
- `error_count`：错误次数

#### 2️⃣ HotspotIdentifier（热点识别器）

**功能**：识别性能瓶颈（慢函数、内存泄漏、高复杂度、紧耦合）。

**识别规则**：
- 🐢 **慢函数**：平均响应时间 > `slow_function_threshold_seconds`（默认 1.0 秒）
- 💾 **内存泄漏**：内存使用 > `memory_leak_threshold_mb`（默认 100.0 MB）
- 🔄 **高复杂度**：圈复杂度 > `high_complexity_threshold`（默认 10）
- 🔗 **紧耦合**：依赖模块数 > `tight_coupling_threshold`（默认 10 个）

**核心方法**：
- `identify_hotspots(metrics_summary, code_analysis)` - 识别代码热点
- `_identify_slow_functions(metrics_summary)` - 识别慢函数
- `_identify_memory_leaks(metrics_summary)` - 识别内存泄漏
- `_identify_high_complexity(code_analysis)` - 识别高复杂度函数
- `_identify_tight_coupling(code_analysis)` - 识别紧耦合模块
- `_calculate_severity(value, threshold)` - 计算严重度

**输出**：`CodeHotspot` 对象列表，包含：
- `hotspot_id`：热点唯一 ID
- `file_path`：文件路径
- `line_number`：行号
- `function_name`：函数名称
- `hotspot_type`：热点类型（`"slow_function"`、`"memory_leak"`、`"high_complexity"`、`"tight_coupling"`）
- `severity`：严重度（1-5，5 最严重）
- `metrics`：指标字典
- `detected_at`：检测时间
- `status`：状态（`"open"`、`"in_progress"`、`"resolved"`）

#### 3️⃣ ArchitectureAnalyzer（架构分析器）

**功能**：分析代码架构（耦合度、内聚度、复杂度）。

**分析指标**：
- 🔄 **圈复杂度**：每个函数的圈复杂度（McCabe 指标）
- 🔗 **耦合度**：每个文件导入的模块数量
- 📂 **依赖列表**：每个文件依赖的模块列表
- 📊 **代码行数**：每个函数的代码行数

**核心方法**：
- `analyze_codebase(path)` - 分析整个代码库
- `_analyze_file(file_path)` - 分析单个文件
- `_analyze_function(node, code)` - 分析单个函数
- `_analyze_class(node, code)` - 分析单个类
- `_calculate_cyclomatic_complexity(node)` - 计算圈复杂度
- `_calculate_coupling(tree)` - 计算耦合度
- `_extract_dependencies(tree)` - 提取依赖列表
- `_calculate_summary(files)` - 计算整体摘要

**输出**：代码分析结果字典，包含：
- `analysis_id`：分析 ID
- `timestamp`：分析时间
- `path`：代码库路径
- `files`：文件分析结果列表
- `summary`：整体摘要（总文件数、总函数数、总类数、总代码行数、平均圈复杂度、最大圈复杂度）

#### 4️⃣ AutoRefactorer（自动重构器）

**功能**：自动应用重构手法（提取函数、提取类、简化条件表达式等）。

**支持的重构手法**：
- 🔧 **提取函数（extract_function）**：将长函数中的代码块提取为独立函数
- 🏗️ **提取类（extract_class）**：将相关的函数和数据提取为独立类
- 🔄 **简化条件表达式（simplify_conditional）**：简化复杂的条件表达式
- 🔗 **减少耦合（reduce_coupling）**：减少模块间的依赖

**核心方法**：
- `generate_refactoring_candidate(hotspot)` - 生成重构候选
- `_read_file(file_path)` - 读取文件内容
- `_apply_refactoring(code, hotspot, refactoring_type)` - 应用重构手法
- `_extract_function(code, hotspot)` - 应用"提取函数"重构
- `_extract_class(code, hotspot)` - 应用"提取类"重构
- `_simplify_conditional(code, hotspot)` - 应用"简化条件表达式"重构
- `_reduce_coupling(code, hotspot)` - 应用"减少耦合"重构

**输出**：`RefactoringCandidate` 对象，包含：
- `candidate_id`：候选唯一 ID
- `hotspot`：代码热点（`CodeHotspot` 对象）
- `refactoring_type`：重构类型
- `original_code`：原始代码
- `refactored_code`：重构后的代码
- `test_results`：测试结果
- `deployment_status`：部署状态
- `created_at`：创建时间
- `deployed_at`：部署时间

#### 5️⃣ RefactoringValidator（重构验证器）

**功能**：在沙箱中验证重构后的代码，确保安全可靠。

**验证流程**：
1. 创建沙箱测试文件（在 `sandbox/` 目录）
2. 写入重构后的代码 + 测试代码
3. 使用 `python -m py_compile` 编译检查语法
4. 捕获编译输出（成功/失败）
5. 清理测试文件

**安全机制**：
- ✅ **隔离环境** → 测试在独立目录中进行，不影响主系统
- ✅ **编译检查** → 只检查语法，不实际执行代码
- ✅ **自动清理** → 测试完成后自动删除临时文件

**核心方法**：
- `validate_refactoring(candidate)` - 验证重构
- `_create_sandbox_file(candidate)` - 创建沙箱测试文件
- `_run_sandbox_test(test_file)` - 运行沙箱测试

**输出**：验证结果字典，包含：
- `candidate_id`：候选 ID
- `hotspot_id`：热点 ID
- `refactoring_type`：重构类型
- `test_passed`：是否通过测试
- `test_output`：测试输出（成功/错误信息）
- `validated_at`：验证时间
