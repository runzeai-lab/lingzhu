## 二、技术心得

### 2.1 测试框架选择心得

**问题**：如何选择适合的测试框架？

**解决方案**：选择`pytest` + `pytest-cov`。

1. **pytest优势**：
   - 简洁的测试语法（无需继承`unittest.TestCase`）
   - 强大的断言重写（assert语句自动生成详细错误信息）
   - 丰富的插件生态（pytest-cov、pytest-mock等）

2. **pytest-cov优势**：
   - 自动测量代码覆盖率
   - 支持多种报告格式（终端、HTML、XML等）
   - 可以设置覆盖率阈值（如：`--cov-fail-under=70`）

**效果**：
- ✅ 快速搭建测试框架
- ✅ 自动化测试运行和覆盖率测量
- ✅ 详细的测试报告和覆盖率报告

### 2.2 测试用例设计心得

**问题**：如何设计完整的测试用例？

**解决方案**：采用"黑盒测试 + 白盒测试"相结合。

1. **黑盒测试**（基于需求和接口）：
   - 测试正常情况（如：`test_decide_safe_command`）
   - 测试异常情况（如：`test_decide_unsafe_command`）
   - 测试边界情况（如：`test_check_autonomy_threshold_exceeded`）

2. **白盒测试**（基于代码实现）：
   - 测试所有公开方法（如：`test_init`、`test_to_dict`等）
   - 测试所有分支路径（如：`check_autonomy`方法的多个分支）
   - 测试所有异常抛出（如：`decide`方法抛出`ValueError`）

**效果**：
- ✅ 高覆盖率（88%）
- ✅ 捕捉到潜在bug
- ✅ 确保代码质量

### 2.3 测试隔离心得

**问题**：如何确保测试之间不互相影响？

**解决方案**：每个测试方法都重新创建测试数据。

**示例**：
```python
def test_decide_safe_command(self):
    """测试 decide 方法 - 安全指令"""
    # 准备测试数据（每个测试方法都重新创建）
    user_command = "生成一篇关于AI的公众号文章"
    system_state = {"cpu": 0.5, "memory": 0.6, "task_queue": 3}
    environment = {"time": datetime.now().isoformat(), "location": "WSL", "network": "connected"}
    
    # 执行
    engine = WisdomDecisionEngine()
    result = engine.decide(user_command, system_state, environment)
    
    # 验证
    assert isinstance(result, DecisionOutput)
    # ...
```

**效果**：
- ✅ 测试之间完全隔离
- ✅ 可以随时单独运行某个测试
- ✅ 测试运行顺序不影响结果
