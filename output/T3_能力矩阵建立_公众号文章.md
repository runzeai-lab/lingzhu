## 一、为什么需要能力矩阵？

在任务T1（优化模型调度策略）中，我实现了**三层调度策略**（思考层/执行层/验证层）和**三种调度策略**（预先安排/动态降级/混合双核）。

但是，还有一个问题：**如何决定哪个任务用哪个模型？**

**问题场景**：
1. 用户说："写一篇关于AI的短文" → 应该用本地小模型（`qwen:0.5b`，零成本）
2. 用户说："编写一个复杂的排序算法" → 应该用云端强模型（`claude`，高成本）
3. 用户说："生成一张猫的图片" → 需要图像生成API（如：DALL-E/Stable Diffusion）

**如果没有能力矩阵**：
- 所有任务都用最强模型（`claude`）→ 成本浪费
- 或者，所有任务都用本地模型（`qwen:0.5b`）→ 质量不够

**能力矩阵的作用**：
- **任务类型 → 最佳模型**的匹配表
- 让调度器自动选择最佳模型（不需要手动指定）

### 2. 添加`get_model_from_capability_matrix()`方法

```python
def get_model_from_capability_matrix(self, task_type):
    """根据能力矩阵获取最佳模型"""
    if task_type in self.capability_matrix:
        return self.capability_matrix[task_type]["model"]
    else:
        # 如果任务类型不在矩阵中，返回默认模型（执行层）
        return self.layers["execution"]["models"][0]
```

### 3. 修改`_pre_arrange()`方法，优先使用能力矩阵

## 五、反思（遇到的问题 + 解决方案）

### 问题1：WSL中运行Python脚本遇到引号转义问题

**现象**：
在WSL中运行复杂Python脚本时，经常遇到引号转义问题（`unexpected EOF while looking for matching '"'`）。

**原因**：
WSL的bash和Windows的Git Bash引号转义规则不同，导致复杂Python脚本中的引号出错。

**解决方案**：
1. **在Windows中创建Python脚本**（使用`Write`工具）
2. **复制到WSL**：`wsl -d Ubuntu -e bash -c "cp /mnt/e/WorkBuddy/Claw/test_capability_matrix.py /opt/trinity/lingzhu/"`
3. **在WSL中运行**：`wsl -d Ubuntu -e bash -c "cd /opt/trinity/lingzhu && python3 test_capability_matrix.py"`

**经验总结**：
- 避免在WSL bash中直接运行复杂Python单行命令
- 优先使用Python脚本文件

### 问题2：缓存机制导致测试不准确

**现象**：
测试能力矩阵时，发现模型分配不符合预期（如：`image_generation`任务返回`claude`，但是没有打印警告信息）。

**原因**：
调度器的**缓存机制**（`model_cache.json`）中有旧记录，导致`get_model_for_task()`方法直接返回缓存的模型，没有调用`_pre_arrange()`方法。

**解决方案**：
1. **清除缓存文件**：`wsl -d Ubuntu -e bash -c "rm -f /opt/trinity/lingzhu/model_cache.json"`
2. **在测试脚本中清除内存缓存**：`scheduler.task_model_cache = {}`
3. **使用`force_refresh=True`参数**：`scheduler.get_model_for_task(task_type, complexity, prompt, force_refresh=True)`

**经验总结**：
- 测试前一定要清除缓存（文件和内存）
- 缓存机制虽然能提高性能，但是会影响测试准确性

### 问题3：`image_generation`任务需要外部API，但是当前返回思考层模型

**现象**：
能力矩阵中，`image_generation`任务的最佳模型是`"external_api"`，但是`_pre_arrange()`方法返回的是思考层模型（`claude`）。

**原因**：
当前（V181.0）还没有集成外部API（如：DALL-E、Stable Diffusion），所以临时返回思考层模型。

**解决方案**（临时）：
在`_pre_arrange()`方法中，如果`model == "external_api"`，打印警告信息，然后返回思考层模型。

```python
if model:
    if model != "external_api":
        return model
    else:
        print(f"[Scheduler] 警告：任务 {task_type} 需要外部API，暂时使用思考层模型")
        return self.layers["thinking"]["models"][0]  # 暂时用思考层，后续集成外部API
```

**长期方案**：
集成外部API（如：DALL-E、Stable Diffusion）到调度策略。
