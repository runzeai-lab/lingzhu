## 二、技术心得

### 2.1 后端API设计心得

**问题**：如何设计RESTful API供前端消费？

**解决方案**：使用FastAPI框架，定义清晰的端点。

**FastAPI优势**：
1. **自动文档**：访问`http://localhost:9000/docs`自动生成Swagger UI文档
2. **类型提示**：使用Pydantic模型定义请求/响应体
3. **异步支持**：原生支持`async/await`
4. **CORS中间件**：可以配置跨域资源共享

**效果**：
- ✅ 快速搭建后端API
- ✅ 自动生成交互式API文档
- ✅ 前端可以轻松消费API

### 2.2 前端可视化心得**

**问题**：如何可视化后端数据？

**解决方案**：使用Chart.js库绘制图表。

**Chart.js优势**：
1. **简单易用**：只需几行代码就可以绘制图表
2. **响应式**：支持响应式设计，适应不同屏幕大小
3. **丰富图表类型**：支持折线图、柱状图、饼图、雷达图等
4. **动画效果**：默认带有平滑的动画效果

**效果**：
- ✅ 决策历史趋势图清晰展示了置信度和风险等级的变化
- ✅ 系统状态卡片直观展示了关键指标
- ✅ 执行历史卡片方便查看最近记录

### 2.3 前后端集成心得**

**问题**：如何让前端和后端协同工作？

**解决方案**：使用CORS中间件 + 相对URL。

1. **CORS中间件**：
   ```python
   app.add_middleware(
       CORSMiddleware,
       allow_origins=["*"],  # 简化：允许所有来源
       allow_credentials=True,
       allow_methods=["*"],
       allow_headers=["*"],
   )
   ```

2. **相对URL**：
   - 前端使用相对URL（如：`/api/system-state`）
   - 这样前端和后端可以部署在不同端口（开发时），或相同端口（生产时）

**效果**：
- ✅ 前端可以顺利从后端获取数据
- ✅ 开发时前后端分离，生产时可以合并部署

## 三、哲学思考

### 3.1 与"稳定根基"的对齐

**"稳定根基"核心原则**（来自SOUL.md三.0节）：
1. **文件进home**：项目/代码/数据必须放`/home/xxx`，绝对不能放`/mnt/c`、`/mnt/h`
2. **内存限一半**：`.wslconfig`设`memory=物理内存50%～60%`，防Vmmem狂涨
3. **网络开镜像**：`networkingMode=mirrored`，WSL与Windows同IP
4. **DNS写死**：`/etc/resolv.conf`写死`8.8.8.8`、`1.1.1.1`，防超时
5. **Docker原生装**：WSL内装`docker-ce`，不装Docker Desktop
6. **GPU靠Windows**：Windows装NVIDIA驱动，WSL内直接用`nvidia-smi`
